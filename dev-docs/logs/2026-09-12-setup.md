# 2026-09-12 — dvpnctl build-out

## Goal
Set up a Sentinel dVPN client so all traffic routes through one tunnel, with a
kill switch that persists until deactivated and fast endpoint switching.

## Findings
- `MathNodes/meile` is the unmaintained 2022 TUI (v0.5.1) depending on the
  removed `sentinelcli`; unusable against sentinelhub-2 today. `meile-gui`
  v2.7.1 is current but has no Arch package for this version. Chosen engine:
  official `sentinel-dvpncli` v5.
- The upstream v5.0.0 release asset is musl-linked; the musl loader is absent on
  the test host. Built a static binary from source (`CGO_ENABLED=0 go build`);
  `install.sh` now tries preinstalled → release → source build.
- `connect <session-id>` already emits wg-quick PostUp/PreDown rules that
  implement a fail-closed kill switch when `AllowedIPs` has a `/0`. No custom
  firewall needed.
- `connect` signs the session handshake, so it needs the wallet key. A root
  system service cannot use the `os` keyring (no unlocked secret service), and
  the `memory` backend has no key. Solution: a `test` keyring under
  `/var/lib/dvpnctl` (0700 root), populated by `install.sh`.
- `query` commands always print YAML: the CLI registers `--output-format` on both
  `query` and `tx`; viper keeps the last binding (tx), so query's flag is
  ignored. Parser uses PyYAML. `tx` output honors JSON.
- Node plan subscriptions are mostly dead (few plans have indexed nodes), so
  pay-as-you-go sessions are the working path. Cheapest wireguard `udvpn` nodes
  are ~12.5 DVPN/GB.
- Session funds are escrowed, not sent: the deposit (`quote × GB`) is refunded
  by `BeginBlock` when the session goes inactive (node offline → `status_timeout`
  = 2h) or on cancel. Max at risk = the per-session deposit, so small sessions
  cap exposure.
- `wg-quick up` failed with a bare `exit status 1` (the SDK sends its stderr to
  /dev/null). Root cause: NetworkManager (`rc-manager=symlink`) wrote
  `/etc/resolv.conf`; openresolv's `libc` subscriber exits 1 on
  `signature mismatch`. Fixed by setting `rc-manager=resolvconf` in
  `/etc/NetworkManager/conf.d/` and taking the file over with `resolvconf -u`.
- RPC nodes are mutually inconsistent: one reported account seq 3 while a tx had
  reached 5, and a stale `query sessions` hid a just-created session, so `up`
  created duplicate sessions. Fixes: read the new session id from the tx's own
  `session_id` event, make `find_active_session` query every endpoint and take
  the max, and reconcile stale/duplicate sessions on every `up`.
- A multi-peer AmneziaWG failover pool was prototyped and dropped: no AWG kernel
  module (userspace is slow), few/costly nodes, and no failover across equal `/0`
  AllowedIPs without a watchdog. Removed; `up`/`switch` cover endpoint changes.

## Delivered
- `dvpnctl` controller (init/address/balance/fund/nodes/best/up/down/switch/
  status/selftest), `systemd/dvpnctl.service`, `install.sh`, README, runbook.
- Sanitized and generalized for public release: all tunables in `config.json`,
  MIT licensed, no personal data, no dependency on MathNodes/meile.

## Open / possible follow-ups
- Optional automatic failover watchdog (probe primary, switch on loss).
- IPv6 DNS/handshake behaviour on networks without IPv6.
